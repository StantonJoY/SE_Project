# Agent 会话记录（D5）

本目录保存 **AI coding agent 的真实会话记录**，用于回答课程的两类问题：
agent 实际承担了什么、什么时候被调用，人类如何审核 / 纠正 / 重定向它们。

## D5 主记录

课程要求 D5 能支撑"从零构建"的完整叙事。7 份记录中，**担任 D5 主记录的是第 1 份**：

> **`60989886ShenJiyun-2026-10-06-v1-build-and-governance.md`** — 从零构建 V1：
> 需求 → 架构 A1–A5 → 治理工件 → 7 个架构元素 → 评估集 → 交接。
> 39 轮 / 1149 次工具调用 / 16 次审批交互，跨 2026-10-06 → 11-02 四个工作周。

选它的理由：它是唯一一份**从空仓库开始**、覆盖完整演进过程的会话；其余 6 份都是在既有代码上
扩展（V2/V3 开发）或做验证（测试/证据/演示），更适合作为**分工与验证环节**的证据，而不是
"从零构建"的证据。

## 这批记录能说明什么

以主记录 ① 为例，它完整保留了这些可核查的事实（不是事后叙述）：

- **人类下指令 → agent 执行 → 人类打断/改向**：26 条干预中，如 INT-1006-10「我们主要目标是要文档完整而不是推项目进度」直接改变了后续所有优先级；INT-1006-15「p5p6 为什么跳过了」迫使 agent 承认跳过了治理步骤；
- **agent 遇到阻塞并上报**：沙箱权限导致 `pwsh` 全挂、测试套件"卡住"、CI 7 次运行 0 job；
- **人类批准了哪些提权**：16 次 `approval/asked` + `approval/decided`，含被允许的范围；
- **工具调用全过程**：1149 次调用与结果（含失败），可直接核对 agent 到底做了什么；
- **没有做的事**：例如 agent 从未修改 `src/compliance/`、`data/*.json`。

## 生成方式

DSH 会话的可读版由本仓库脚本生成，可复现、非手写：

```bash
node transcripts/tools/export-session.js \
     transcripts/raw/2026-11-17-session.v4.jsonl.zstd \
     transcripts/60989886ShenJiyun-2026-11-17-main-v2-integration.md
```

脚本只做排版（截断长文本、跳过模型内部 `reasoning` 块、标注平台注入内容），
**不改写用户消息与助手正文**。原始字节在 `raw/` 中完整保留，可独立校验。

### 人工干预索引是后加的

上述导出脚本**不生成**「人工干预索引」表。首版导出只有 4 份会话带此表；`2026-10-06` 与
`2026-11-17` 两份是纯导出、无标注，`2026-10-30` 的标注以小节形式散在文末。

补充方式（2026-11-24）：**只在文件开头插入索引一节 / 把文末小节转成表格，正文一字不改**。
插入的表格与人名不对原文做任何增删，每条都给出可回查的轮次编号。这样既满足"每份记录
都要标注干预与理由"，又不破坏"原始导出未被改写"这一前提。

> 后续会话的可读版放本目录，并在此表登记。DSH 原始会话 `session.v4.jsonl.zstd` 放在
> `raw/`。V2 发布的校准导出放在 `exports/`，按校准选录保存发言及工具调用汇总。
