## 1. 核心结论：V1 是无状态系统

**一句话**：**V1 没有任何请求间状态。** 每次推荐都是独立的、可丢弃的单轮计算。

但"无状态"不等于"没有记忆设计"——课程要求把**决定了什么、以及为什么**写下来。以下三节分别处理：
**（§2）确实存在的三个存储**、**（§3）刻意不做的两类状态**、**（§4）无状态带来的架构后果**。

## 2. 确实存在的存储（本项目只有三个）

### S1 · 审计日志（唯一真正的 durable store）

| 字段 | 内容 |
|---|---|
| **类别** | Durable store（跨运行、跨请求存活） |
| **载体** | `logs/audit.jsonl`（JSONL 追加写，路径由 `config.yaml` 的 `audit.log_path` 单点控制） |
| **内容** | 场景特征、候选集规模、LLM 原始输出、过滤结果、最终输出、降级原因码、`model_version`、`prompt_version`、`threshold` |
| **写入策略** | **每次推荐请求恰好追加 1 条**（`INV-ADS-012`）；**只追加，不修改、不删除**；异常路径也必须落盘 |
| **读取策略** | 离线评估与重放时全量读取；运行期**决策路径不读它**（回读会让证据反过来影响决策） |
| **归属** | `src/audit/`（P6 待建） |
| **保留期** | ⚠️ **待决**（见 §5）——建议 V1 采用**有限保留 + 可配置**，而非直接声称 7 年 |
| **隐私** | ⚠️ **含潜在个人信息**：`user_tags` 可能构成 PII 或 PII 代理（如 `student` 身份、`parent` 身份）。见 §5 |

> **架构要点**：审计是**只写不读**的存储。这一条很关键——若决策路径读取自己的历史，
> 就会出现"过去的证据影响现在的决策"，等于引入了隐藏状态，`INV-ADS-004`（解释/证据不得影响决策）的类比约束会被破坏。

### S2 · 素材库（启动期加载的只读内存驻留）

| 字段 | 内容 |
|---|---|
| **类别** | 配置性数据（非"状态"——它在运行期不变） |
| **载体** | `data/ads.json` → 启动加载进内存（`AdRepository`） |
| **写入策略** | **仅启动期**；加载后进程内**只读**；整批 fail-closed（`INV-ADS-015`） |
| **读取策略** | 每次请求读取以构建候选集（`filter_by_scene`）与合规检查 |
| **归属** | `src/ads/` |
| **保留期** | 进程生命周期；随进程退出而消失 |
| **隐私** | 无——素材是自造广告文案，不含用户数据 |

### S3 · 运行配置（初始化后冻结）

| 字段 | 内容 |
|---|---|
| **类别** | 配置（非状态） |
| **载体** | `config.yaml` + 环境变量覆盖 |
| **写入策略** | **仅启动期读取一次**；`INV-ADS-012` 要求把用到的阈值写入审计证据，以便事后复现 |
| **读取策略** | 允许读取；**不可在运行期修改**（课程行 1457：Config immutable after initialization） |
| **归属** | 进程级 |
| **保留期** | 进程生命周期 |

> **课程要求对照**（note 行 1452–1457）：配置治理四条规则——每个环境变量映射到唯一配置键、
> **非法值在启动时大声失败（FAIL LOUDLY）**、无环境变量则用默认值、**初始化后不可变**。
> 本项目的 `config.yaml` 目前只是静态文件，**尚未实现"启动期校验 + 冻结"** → 已记入 §6 技术债 `TD-006`。

## 3. 刻意不做的两类状态（以及为什么）

课程把内存分为两类，本项目**两类都不做**，且各自都有明确的架构理由。

### 不做 Checkpoint（无暂停/恢复）

| 项 | 内容 |
|---|---|
| **课程定义** | Checkpoint = per-workflow 状态，用于 pause / resume（note 行 1398） |
| **本项目** | **不做**。没有暂停语义，没有恢复语义 |
| **理由** | Checkpoint 的存在前提是**有需要被人中断并恢复的流程**。本项目的失败路径是**终止并降级为 `no_ad`**（ADR-002 D1），而不是"挂起等人工"。没有等待，就不需要保存中间状态 |
| **代价** | 无法支持"重试后展示次优候选"、"人工复核队列"这类需要保留现场的能力 |
| **重开条件** | 若引入运行时人工复核（ADR-002 T-2）或引入多轮交互（ADR-001 T4），**必须新增 checkpoint 元素并重写本文** |

### 不做 Durable Knowledge Store（无跨会话知识）

| 项 | 内容 |
|---|---|
| **课程定义** | Store = cross-thread durable knowledge（note 行 1404） |
| **本项目** | **不做**。没有跨会话持久知识 |
| **理由** | V1 的场景特征是**无状态单轮输入**（`scope.out` 明确不做用户画像与多轮上下文记忆）。没有"以前发生过什么"影响"这次选什么"，就不需要跨会话知识 |
| **代价** | 无法做长期个性化、无法从历史反馈中学习 |
| **重开条件** | 若要引入用户画像或历史偏好，需重开 `ADR-001`（触发 T4）并重新设计隐私与保留策略 |

> **与课程的差异及理由**（必须显式声明）：VHIS 的 Memory Design 同时含 Checkpoint（90 天）与 Store（7 年），
> 因为它**既有评审暂停、又有 7 年监管留存**。本项目两者都没有——**不是遗漏，是两个已论证的取舍。**

## 4. 无状态带来的架构后果（本文最重要的部分）

无状态不是一个"省事的默认"，它**倒逼出三条结构性要求**：

| # | 后果 | 影响的 ASR / 不变量 |
|---|---|---|
| **M1** | **所有上下文必须每轮重建**。因为没有任何东西跨轮存活，所以"AI 看到什么"必须由一个**显式装配过程**产出，而不能依赖累积 | `ASR-ADS-A3-01`、`INV-ADS-014` |
| **M2** | **上下文装配是结构元素，不是优化**。6 层上下文的预算、五步装配、compaction、re-injection 全部必须在**单次请求内**完成 | `ASR-ADS-14`、`RP-010` |
| **M3** | **compaction 只可能由"单轮上下文过大"触发，不可能由"历史累积"触发**。因此 85% 阈值的含义与 VHIS 不同：VHIS 是防历史膨胀，本项目是防**候选集 + 指令超预算** | `INV-ADS-014` |

**M3 的一个直接推论**：本项目的 compaction 风险**主要来自候选集规模**，而非对话轮次。
所以 `A-04` 假设（候选集不会超预算，当前仅 8 条素材）是**这条设计的唯一支点**——
素材扩到 30~50 条（OQ-003）时，`concern-clusters.md` §4 已标记**必须重测**。

**附：为什么历史层（第 4 层）标"不适用"而不是省略**

课程六层架构中第 4 层是 HISTORY。本项目无历史，但**必须显式声明"不适用 + 理由"**，
而不是默默省掉一层（见 `asr-register.md` §3.1）。理由：省略会让后来者以为"忘了做"，
显式声明才让"这是一个决定"可被审计。

## 5. 保留期与隐私（两个必须由团队决定的问题）

### 5.1 保留期

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）**: 有限保留 + 可配置 | 如 90 天，`config.yaml` 可调；到期轮转删除 | 无法支撑长期合规审计 |
| **B**: 声称 7 年 | 对齐课程 VHIS 的监管留存口径 | **本地 JSONL 文件无法提供防篡改与 7 年可靠性**；且与 §5.2 隐私冲突 |

> **不建议直接照抄 VHIS 的 7 年**：课程的项目目录里 `logs/` 已被 `.gitignore` 排除，
> 载体是普通追加文件——它**没有哈希链、没有只追加介质保证**。
> 声称 7 年而载体不支持，属于**自我欺骗式合规**，评审时反而更容易被问倒。
> 若确需长保留，正确做法是引入防篡改机制（课程 B3 的 WAL + 哈希链模式），那是一次架构演进。

### 5.2 隐私（真实风险，不能略过）

审计记录含 `user_tags`（如 `student`、`parent`、`office_worker`、`gamer`）。
**这些是 PII 代理**：单独看是标签，结合时间戳与设备可构成可关联的行为记录。

| 风险 | 缓解（建议） |
|---|---|
| 标签可关联到个体行为 | 审计中**只记标签集合的哈希**，或明示为"聚合级"数据；原始标签不入库 |
| 记录可无限增长 | 配合 §5.1 选项 A 的轮转删除 |
| 非授权访问 | 本地单进程，V1 无多用户；但**不得把 `logs/` 提交进仓库**（`.gitignore` 已排除） |

> 课程对应：VHIS 用 `SEC-002`（"Authorized roles only; 7-year audit"）与"Patient data: hashed refs"处理同类问题。
> **本项目当前没有对应的隐私不变量** → 已记入 §6 技术债 `TD-007`，建议新增一条 `REQ-ADS-SEC-003` + 不变量。
