# ADR-008：分层上下文结构与装配流水线

## 1. 背景：为什么单独立一条 ADR

模型每一轮看到什么，决定了它能做什么、不能做什么。如果"看什么"由代码随手拼、或者由模型
自行累积，那么**权威边界会被上下文悄悄改变**：同样一套合规规则，放在 prompt 开头和夹在
两万个 token 之后，遵守率是完全不同的两件事。

课程把这件事列为 D2 的**点名项**：不只是"实现上下文装配"，而是"把**设计**呈现出来——
分层结构、装配流水线、预算上限与压缩阈值、压缩后的约束重注入策略"。

此前这些设计只存在于 `src/selector/context.py` 的实现与注释里，ADR-001 只提到
`compaction` 与 `re-inject` 两个词。评审按课程条目翻 ADR 是找不到的。**本条 ADR 补这个缺口，
不改变任何实现。**

## 2. 决策 D1：六层结构（顺序即装配顺序）

| # | 层 | 内容 | 由谁写 | 可否裁剪 |
|---|---|---|---|---|
| ① | `SYSTEM` | 身份与职责（"你是候选选择器，你不拥有最终决定权"） | 代码常量 | **永不裁剪** |
| ② | `INSTRUCTIONS` | 不可协商约束（闭集、不得改写、输出 schema、建议性质、禁用外部知识） | 代码常量 | **永不裁剪** |
| ③ | `RETRIEVED` | 候选列表（`ad_id / 品类 / 标题 / 标签`） | 确定性排序后的候选 | 可压缩（见 D4） |
| ④ | `HISTORY` | 对话/轮次历史 | **恒为空**（V1 无状态单轮） | 不适用 |
| ⑤ | `STATE` | 场景语义（时段/设备/用户标签 + 档位含义） | 场景解析器 | 不裁剪（极小） |
| ⑥ | `USER` | 当前任务（"选出与场景最匹配的一条"） | 代码常量 | 不裁剪 |

两条“显式声明”而非“省略”的决定：

- **`HISTORY` 层恒空但必须存在**。省略会让后来者以为忘了做；显式标注"不适用 + 理由"
  （`memory-design.md` §4 M3）才让"这是一个决定"可被审计。
- **`NEVER_TRIMMED = {SYSTEM, INSTRUCTIONS}`** 写进代码，压缩只允许作用于 `RETRIEVED`。

## 3. 决策 D2：五步装配流水线

```
① DEDUPLICATE  去重（同 ad_id 只留一条）
② PRIORITIZE   确定性排序（按 ad_id 升序，不依赖模型打分）
③ BUDGET       估算 token → 三档路由（DIRECT / SUMMARIZE / OVER_BUDGET）
④ COMPACT      仅 SUMMARIZE 档裁剪候选（保留前 5，其余折叠为计数）
⑤ ASSEMBLE     按六层顺序渲染；**压缩后重新注入第 ② 层**
```

每一步都是**纯函数**：无时钟、无随机、无 locale 依赖，同一输入逐位一致（`INV-ADS-003` 的
可复现性要求）。装配器本身无状态，每次 `assemble()` 独立，可重复调用。

## 4. 决策 D3：预算上限与压缩阈值

| 参数 | 值 | 单一来源 |
|---|---|---|
| token 上限 | **2000** | `config.yaml` → `selector.context_budget_tokens` |
| 压缩阈值 | **85%** → 1700 | `COMPACTION_THRESHOLD_RATIO = 0.85` |
| token 估算 | `ceil(len(text) / 3)` | `count_tokens()`，**保守**（中文约 3 字符/token） |

三档确定性路由（`route_budget`）：

| 估算值 | 档位 | 行为 |
|---|---|---|
| ≤ 1700 | `DIRECT` | 直接装配 |
| ≤ 2000 | `SUMMARIZE` | 压缩候选摘要后装配 |
| > 2000 | `OVER_BUDGET` | **上层降级为 `no_ad`**（原因码 `budget_exceeded`，`RP-010`） |

**为什么是"估算"而不是真实 tokenizer**：真实 tokenizer 是一个外部依赖，而本项目的硬约束是
零外部依赖 + 确定性可复现。`ceil(len/3)` 刻意偏保守，宁可多留余量也不低估。
代价是它对英文/JSON 偏保守约 3 倍——这个代价在 V2 显式暴露过（见 §6）。

## 5. 决策 D4：压缩后必须重注入，且可被断言

压缩在 `SUMMARIZE` 档执行：**只保留排序后的前 5 条候选**，其余折叠为一行
"（另有 N 条候选因预算被折叠，未列出）"。模型因此始终知道"还有东西没看到"，
不会误以为候选只有 5 条。

**重注入**：无论是否发生压缩，第 ② 层 `INSTRUCTIONS` 都在最终 prompt 中重新出现一次，
并有固定标记 `REINJECTION_MARKER = "约束（不可协商）："` 供测试断言。

依据不是直觉，是课程实测：compaction 会把 Instructions 推到低注意力位置，造成
"规则存在但不可见"，约束满足率 **98% → 72%**。

## 6. 被否的备选

| 备选 | 为什么不选 |
|---|---|
| 让模型自己累积/管理历史 | 状态会变成模型私有，审计无法复现；且 V1 本就无状态 |
| 按字符数直接截断 prompt | 截断可能切掉约束或候选，属于"静默降级" |
| 只保留 `SYSTEM + USER` | 丢掉候选与场景，模型只能瞎选 |
| 引入 tiktoken 等真实 tokenizer | 破坏零依赖与确定性；且估算偏差已用保守设计吸收 |
| 不做 `OVER_BUDGET` 降级，硬塞进去 | 会突破预算并让模型在超长上下文下失去指令跟随能力 |

## 7. 后果与已知风险

- **好处**：模型能看到什么、看不到什么，完全由代码决定且可审计；压缩行为有断言锁定；
  预算超限一律降级为 `no_ad`，不会"偷偷截断后继续"。
- **代价 1**：`ceil(len/3)` 对英文字节偏保守。V2 的相关性接口改用 UTF-8 字节估算后更保守
  （约 3 倍），导致 2000 预算只装得下 4 条候选（`ADR-006` D8）。两套估算口径统一属 V4。
- **代价 2**：`OVER_BUDGET` 是硬失败。候选集过大时宁可不出广告——这是安全优先的选择，
  但在候选密集的场景会降低出广告率。
- **未覆盖**：本 ADR 只描述 V1 选择器。V2 的相关性接口（`selector/relevance.py`）有自己的
  提示词与字节预算，不在本条范围内。

## 8. 重开条件

1. 接入真实 tokenizer，或改变估算方式（届时必须同步改 `count_tokens` 与全部预算断言）；
2. 引入多轮对话 / 可恢复状态（`HISTORY` 层从"恒空"变为真实内容）；
3. token 上限或压缩阈值调整超过 50%；
4. 压缩策略从"保留前 N 条"改为其他形式（如按类型配额）。
