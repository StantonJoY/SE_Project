## 1. Context

### 1.1 问题

课程门禁 4 要求"prompt 或 model 变更须先 replay 固定评估集过质量阈值"。本项目在 P4–P6
完成了全部 7 个架构元素并端到端跑通后，**门禁 4 仍是空转的**——因为：

- `eval/` 目录不存在（无评估集、无 replay runner）；
- 仓库无任何 prompt 文件（`prompts/` 为空），故**门禁的触发条件本身从未成立**；
- 期望值的判定口径未定（`OQ-005`）。

登记为 `TD-003`（评估债）与 `TD-019`（门禁 4 不可用）。

### 1.2 为什么这不是"补个数据文件"，而是架构决策

课程把 **token budget** 与 **explanation quality** 明确列为**架构性的**（`ASR-ADS-A3-01/02`）；
**评估集决定"什么算对"**，其影响力与之同级，理由有三：

1. **它定义验收语义。** 评估集说"这条场景应当选出 `ad_004`"，这条断言就**成为规格的一部分**。
   换一套评估集，同一份实现可以从"达标"变为"不达标"——这就是权威。
2. **它是门禁 4 的判据来源。** 没有它，门禁 4 无判据可依，只是死代码；
   有了它，它成为**合并阻断**的依据（`INV-ADS-016`）。
3. **它是"AI 建议"质量的可观测入口。** 闭集选择 + 严格 schema 保证了**形式**正确
   （`INV-ADS-002/003`），但**实质**选得好不好，只能由评估集观测。

### 1.3 约束

- 本项目**无运行时人类复核**（`ADR-002` D1），故不展示即 fail-closed；评估是**离线**的。
- 评估集是**只读验证资产**，**不得进入运行时决策路径**（否则会把"预期答案"泄漏给系统，
  评估即失去意义——这与 BUILD 不得读测试源码是**同一条 blindness 逻辑**）。
- V1 无真实 LLM（供应商选型见 `OQ-001`），replay 走 `MockLLM`；
  真实 LLM 接入属 P8，届时口径可能需重标定。

### 1.4 待决项（本 ADR 解决）

`OQ-005`：期望广告由**人工标注**，还是按**品类匹配**判定。
通过率阈值取值，以及"预期降级"用例是否计入分母。

## 2. Decision

### D1 — 评估集为**一等架构资产**，登记于 blueprint §4（⑧）

`eval/` 在新顶层包，须登记入 `architecture-blueprint.md` §4 与 `AGENTS.md` ④（`AGENTS.md` ⑦ 的要求）。
其**权威级别 = 只读验证资产**：**不参与"是否展示"的裁决**，只在 CI 中判定合并可否放行。

### D2 — 判定口径采用**人工标注为主**（`OQ-005` 记为「甲/混合」）

每条用例同时携带：

| 字段 | 作用 |
|---|---|
| `expected` | `ad` \| `no_ad`（**期望系统做什么**） |
| `expected_ad_id` | **人工标注的正确答案**（提供强信号） |
| `expected_category` | 品类约束（标注为 `null` 时的退路） |
| `expect_reason` | 期望降级时，期望的原因码（可为 `null` 表示任一） |
| `basis` + `anchors` | **这条用例为何存在**（依据哪条 REQ/INV/ASR，或哪个真实失败场景） |

**标注由 agent 自造为主，人类审查后可增改。**

> **关键取舍**：品类匹配（只校验"选对了品类"）无法测出**同品类内选错**。
> 本项目素材库中同品类有多条（如 `ad_010`/`ad_011` 同为 gaming），
> 故必须用 `expected_ad_id` 才有分辨力。

### D3 — **分母分离**：`MUST_FAIL` 用例单独统计，不作为阻断理由

评估集分三类标签：

| 标签 | 含义 | 是否计入阻断分母 |
|---|---|---|
| `MUST_PASS` | 应该有广告 | ✅ **计入** |
| `MUST_FAIL` | **应当降级**（合规拒绝 / 超预算 / 注入 / 低置信度 …） | ❌ **不计入** |
| `MUST_FAIL_ON_REPLAY` | 已知的、被接受的失败（记录在案，不修） | ❌ 不计入，但**必须列出** |

**理由（人类指示「FAIL 也是一种情况」）**：
**系统正确地说不，与正确地说好，是同等重要的观测量。**
若把预期降级计入分母，则增加降级用例会**稀释**通过率，使 95% 这个数失去意义——
更糟的是，它会激励"少写降级用例"的反向压力。分母分离使两者各自可读。

### D4 — 通过率阈值 = **0.95**，且只作用于 `MUST_PASS` 分母

- `MUST_PASS` 达成率 ≥ 0.95 → 通过；< 0.95 → **阻断**（退出码 1）。
- 阈值**单点来源**：`config.yaml`（配置治理规则 1–4，`FAIL LOUDLY`）。
- **`MUST_FAIL` 与 `MUST_FAIL_ON_REPLAY` 的达成情况必须打印**，但不影响退出码。

### D5 — replay 必须走**完整管道**，不得绕过

`eval_runner` 调用 `app.pipeline.recommend`（与生产同一条路径），**不得**直接调
`compliance.run_compliance` 或 `selector` 内部函数"抄近路"。理由：绕过会漏掉
阈值 gate、timeout gate、审计写入、注入门——**评估结果将不再代表系统行为**。

### D6 — 违规数是**独立于通过率**的第二判据

无论通过率多高，只要出现下列任一，replay **直接判不通过**（违规为硬约束，不可用比例稀释）：

| 违规 | 依据 |
|---|---|
| 展示了未经合规过滤的广告（`compliance_escape_count > 0`） | `INV-ADS-001` |
| 选中候选集外的 `ad_id` | `INV-ADS-002` |
| 审计条数 ≠ 1 | `INV-ADS-012` |
| 输出未通过 render schema | `REQ-ADS-FR-004` |
| 解释影响了决策（`ad_id` 变化） | `INV-ADS-004` |

> **语义区分**：通过率是**质量**判据（允许 5% 未达）；违规是**正确性**判据（零容忍）。
> 二者混为一谈会让"5% 容忍"意外地容忍安全违规。

### D7 — 评估集**独立于其被测系统**演进（blindness 的评估侧对偶）

- 评估集**不得**由被测实现的输出反向生成（否则退化为"把当前行为固化为正确答案"）。
- 评估集**不得**被实现读取为输入（运行时不可见）。
- 新增/修改用例须记录 `basis`：**说明它守护什么**，而非"让测试变绿"。

## 3. Rationale

| 决定 | 支撑理由 |
|---|---|
| D2 人工标注 | 唯一能测出同品类内选错的方案；且与"AI 是顾问"的定位一致——顾问的好坏要看**具体建议**，不是"类别对不对" |
| D3 分母分离 | 直接来自人类指示；且避免"降级用例越多、通过率越低"的错误激励 |
| D4 阈值 0.95 | 人类指示（仅做 demo）；非 100% 是**承认真实系统有失败**，与 `MUST_FAIL_ON_REPLAY` 机制配套 |
| D5 走完整管道 | 否则评估测的是"某个函数"，不是"系统行为"；与课程 Tier 3 的意图一致 |
| D6 违规零容忍 | 课程把 `compliance_escape_count == 0` 列为**最重要 monitor**；安全不得被比例容忍 |
| D7 独立演进 | 与 blindness invariant ①（BUILD 不得读测试）**同一条逻辑**：被测者不得看见判据 |

## 4. Alternatives

| 备选 | 为何未采纳 |
|---|---|
| **纯品类匹配**（`OQ-005` 乙） | 无法分辨同品类内的错误选择；对 `ad_010`/`ad_011` 这类同品类素材完全无分辨力 |
| **纯人工标注、agent 不产出** | 21+ 条全由人类逐条写，成本高且阻塞进度；人类审查 agent 产出更高效 |
| **阈值 100%** | 与"仅做 demo"和"FAIL 也是一种情况"矛盾；且 100% 会逼出"删掉难例"的反向激励 |
| **违规计入通过率**（不独立判据） | 会让 5% 容忍意外覆盖安全违规——**不可接受** |
| **replay 直接调 compliance 与 selector** | 漏掉阈值/timeout/审计/注入门，评估结果不代表系统行为 |
| **把评估集放在 `src/` 下** | 会使其成为运行时可见资产，违反 D7 的 blindness 对偶；且 S1 的"元素↔模块"映射不应被验证资污染 |

## 5. Consequences

**收益（+）**

- 门禁 4 **首次具备判据**，从空转变为可阻断（`TD-019` 可关闭）。
- 评估集使"AI 建议质量"成为**可观测、可回归**的量，而非主观判断。
- 违规的零容忍使**安全判据与质量判据**在结构上分离，避免互相稀释。
- `basis` + `anchors` 字段使每条用例**可追溯到需求**，评估集本身成为可审计工件。

**代价（−）**

- 维护成本：素材库或场景规则变化时，评估集可能需同步（登记为重开条件）。
- 95% 阈值意味着**允许 5% 失败**——若某类失败其实不可接受，须靠 `MUST_FAIL` 标签或
  违规判据显式排除，而非指望阈值拦住它。
- `MUST_FAIL_ON_REPLAY` 有**掩盖风险**：把不该接受的失败登记为"已知"，即可不修。
  缓解：该标签**必须附 `basis` 说明理由**，且列入 D6 报告。

**引入的新债**

- `TD-025`：评估集与素材库的同步机制未建立（素材变更后评估集可能失效）。
- 真实 LLM 接入（P8）后，走 `MockLLM` 标定的口径**需重标定**。

## 6. Re-open Triggers

| # | 触发条件 | 必须动作 |
|---|---|---|
| **T1** | `MUST_FAIL_ON_REPLAY` 条目 > 3 条，或某条存续超过一轮 | **重开本 ADR**——"已知失败"过多即等于降低标准 |
| **T2** | P8 接入真实 LLM 后，`MUST_PASS` 达成率 < 0.95 | 重标定口径与阈值（**预期发生**，非异常） |
| **T3** | 出现任一 D6 违规（即使通过率 100%） | **立即重开**，并触发 `INV-ADS-001` 的 `ADR-001` T1 |
| **T4** | 素材库或场景规则发生变更，导致 ≥ 20% 用例失效 | 重标定评估集 |
| **T5** | 人类审查后大幅增改用例（> 30%） | 视为口径变更，重开本 ADR |
| **T6** | 有人提议把评估集纳入运行时（哪怕只读） | **立即重开**——违反 D7 的 blindness 对偶 |
