# 场景化广告推荐引擎 — V1 需求与功能点草案

> 状态：讨论稿 · 2026-09-28 · **本文件固定为 V1 基线**
> 定位：课程 CS5351 选题，V1 为最简版，**不含 RAG、不含竞价**。
> AI 组件 = LLM 决策层；安全边界 = 确定性合规过滤层。
> 后续迭代：V2 候选 = 报价竞价框架，见 `requirements-v2-bidding-draft.md`（需求先行整理，不在本文件范围）。

---

## 1. V1 范围界定

### 做什么
- 给定一批本地广告素材（结构化 JSON），输入用户场景特征（时段 / 设备 / 用户标签），系统选出一条广告并渲染展示。
- 选择由 LLM 完成（真实 AI 组件）；**最终展示必须经过确定性代码的合规校验**（安全边界）。

### 不做什么（V2+ 再做）
- ❌ RAG / 向量检索（V3 加）
- ❌ 接入真实广告投放平台 / 实时竞价（V2 加）
- ❌ LLM 自由生成全新文案（V1 只做"选择"，不做"创作"）
- ❌ 用户画像系统 / 多轮上下文记忆
- ❌ Web 前端界面（V1 渲染 = 返回 JSON / 简单 HTML）

## 2. V1 核心流程（无 RAG）

```
场景特征输入（time_slot / device / user_tags）
        ↓
① 规则预筛（确定性代码）：按场景硬约束先剔除明显不合规的候选
        ↓
② LLM 选取（AI 组件）：从候选集中选一条，输出结构化 JSON
        ↓
③ 合规过滤（确定性代码·安全边界）：违禁词 / 品类禁忌 / 场景硬约束 / schema 校验
        ↓
④ 渲染输出：返回最终广告（JSON / HTML），失败则降级
        ↓
⑤ 审计日志：记录 场景 → LLM 原始输出 → 过滤结果 → 最终输出
```

关键设计：**LLM 只在候选集内做选择（闭集决策），不能自由输出任意广告**；
即使 LLM 输出不合规内容，确定性过滤层也会拦截——AI 是顾问，代码是执行官。

## 3. 功能点清单

### M1 广告素材库
- F1.1 素材加载：从本地 JSON 文件加载广告素材库
- F1.2 素材字段：每条素材含 `ad_id / title / copy / category / target_tags / scene_restrictions / banned_check`
- F1.3 素材增删改查：简单 CRUD（命令行或 API）

### M2 场景输入
- F2.1 场景特征：`time_slot`（morning/afternoon/evening/night）、`device`（mobile/desktop/tablet）、`user_tags`（简化标签数组）
- F2.2 输入校验：非法/缺失字段直接拒绝，不进入 LLM

### M3 AI 推荐决策（LLM）
- F3.1 候选集构建：规则预筛后得到候选广告集（含"候选为空"情况）
- F3.2 LLM 选择：给定场景特征 + 候选集（含各广告摘要），LLM 返回选中的 `ad_id`
- F3.3 结构化输出：LLM 必须输出合法 JSON（`ad_id / reason / confidence`），由确定性代码解析
- F3.4 低置信度处理：`confidence` 低于阈值时，结果视为不可信，走降级

### M4 合规过滤（确定性代码·安全边界）
- F4.1 违禁词过滤：文案/标题命中违禁词表 → 拒绝
- F4.2 品类禁忌：敏感品类（医疗、金融承诺等）不在展示白名单 → 拒绝
- F4.3 场景硬约束：广告声明的场景限制与当前场景冲突（如夜间不推游戏、校园不推成人）→ 拒绝
- F4.4 输出 schema 校验：LLM 输出必须是合法 JSON，字段类型与取值合法，`ad_id` 必须存在于候选集
- F4.5 拒绝/降级策略：任一校验不过 → 不展示该广告，返回降级结果（无广告）

### M5 渲染与日志
- F5.1 渲染输出：返回结构化推荐结果（广告 + 理由 + 置信度），或"无广告"
- F5.2 审计日志：每次请求记录 场景、候选集规模、LLM 原始输出、过滤结果、最终输出

### M6 工程基础（为课程交付服务）
- F6.1 离线测试：`test/offline` 覆盖全部确定性规则与 schema 校验
- F6.2 固定评估集：内置评估用例（场景 → 期望广告品类），供语义评估 gate replay
- F6.3 配置管理：LLM 模型、API key、超时、阈值均可配置
- F6.4 API 降级：LLM 调用失败/超时 → 确定性兜底（不展示广告，不崩溃）

## 4. 需求条目（ID / 类型 / 优先级 / 验收标准）

| ID | 类型 | 需求 | 优先级 | 机器可检查的验收标准（Fit Criterion） |
|---|---|---|---|---|
| REQ-001 | Functional | 系统从本地 JSON 加载广告素材库 | Must | 加载后素材条数 = 文件条数，重复 ad_id 报错 |
| REQ-002 | Invariant | 每条素材字段完整且合法 | Must | 全量素材通过字段 schema，通过率 100% |
| REQ-003 | Functional | 场景输入（时段/设备/标签）必须通过校验 | Must | 非法输入被拒绝并返回明确错误 |
| REQ-004 | Functional | LLM 在候选集内选择广告 | Must | 返回的 ad_id 必须存在于候选集 |
| REQ-005 | Invariant | LLM 输出必须为合法结构化 JSON | Must | schema 校验通过率 100%，失败走重试/降级，违规零展示 |
| REQ-006 | Invariant | 展示的广告必须全部通过确定性合规过滤 | Must | 已展示广告合规通过率 100%（零逃逸） |
| REQ-007 | Invariant | 敏感品类（医疗、金融承诺等）禁止展示 | Must | 敏感品类广告展示数为 0 |
| REQ-008 | Invariant | 含违禁词的广告禁止展示 | Must | 违禁词命中广告展示数为 0 |
| REQ-009 | Invariant | 广告不得违反自身场景限制 | Must | 违反场景限制的广告展示数为 0 |
| REQ-010 | Invariant | LLM 低置信度/异常输出不得直接展示 | Must | 低置信度样本零展示，全部走降级 |
| REQ-011 | Functional | 无候选/LLM 失败/过滤全拒时降级为"无广告" | Must | 上述场景返回明确结果，不崩溃 |
| REQ-012 | Functional | 渲染输出结构化推荐结果 | Must | 输出符合 render schema（广告/无广告两种形态） |
| REQ-013 | Functional | 每次请求写入审计日志 | Must | 每次请求恰好 1 条日志，字段完整 |
| REQ-014 | Quality | 端到端推荐延迟可控 | Should | 离线评估 p95 延迟 ≤ 5s |
| REQ-015 | Quality | 确定性部分可复现 | Must | 固定输入下确定性过滤结果零差异 |
| REQ-016 | Security | LLM 输出不得含可执行指令/提示注入 | Must | 注入样本 100% 被拦截或标记 |
| REQ-017 | Governance | 代码/Prompt 变更须更新 AI-use 日志 | Must | CI AI-use 日志 gate 通过 |
| REQ-018 | Performance | 单次推荐 LLM token 消耗有上限 | Should | 超预算被截断并记录 |
| REQ-019 | Functional | 内置固定评估集供语义评估 gate 使用 | Must | 评估集 ≥ 20 条，可一键 replay |
| REQ-020 | Quality | 每个验收标准至少 1 个测试；每个不变式至少 1 个失败测试 | Must | CI 全部通过，失败测试确实会失败 |

> 说明：REQ-001~REQ-020 是 V1 草案。课程 D1 要求 YAML 格式 + JSON Schema + CI 校验，本表为内容底稿，后续转 `requirements.yaml`。
