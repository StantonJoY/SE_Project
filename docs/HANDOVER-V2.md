## 4. 转向 V2 的开发建议

### 4.0 V2 的语义转变（先想清这个）

| | V1 | V2 |
|---|---|---|
| 决策 | 从候选集**选出最合适的一条** | 在候选集内按 **relevance × 报价** 竞争 |
| 结果 | 展示 | **成交并计费** |
| LLM 角色 | 闭集选择（advisory） | **只给相关性建议**（`REQ-ADS-ARCH-012`） |
| 状态 | **无状态单轮** | **预算跨请求累积** |
| 计费 | 无金额概念 | **整数分精确入账** |

V2 的 19 条候选需求已在 `docs/req/requirements.yaml` 的 `candidate_requirements` 中，
底稿在 `docs/req/requirements-v2-bidding-draft.md`。

### 4.1 ⚠️ 两个必须先解决的设计冲突

#### 冲突一：**状态设计**（最根本）

- V1 的 `memory-design.md` §3 明确论证：**无状态、无检查点、无持久会话**。
  连"产物不存在"都被当作设计决策来论证。
- V2 的 `REQ-ADS-ARCH-005` 要求 `0 ≤ spent ≤ total` 且 `remaining = total − spent`
  —— **`spent` 必然跨请求累积**。

**这不是"加个字段"，而是对 V1 结论的修订。** 建议：

1. 在 `docs2/architecture/` 新建 `memory-design.md`，**显式引用** V1 的结论并说明**为何 V2 不同**
2. 决定账本存储位置（见冲突二）
3. 新 ADR 记录该决策

#### 冲突二：**审计只写不读 vs 预算必须可读**（真冲突）

- V1 的 `memory-design.md` §2 S1（**不变量级**）：
  **决策路径禁止回读审计历史** —— 回读会引入隐藏状态，使同一输入在不同历史下产出不同决策。
- V2 判断"预算是否耗尽"**必须读 `spent`**。

**三个候选方案**（须新 ADR 定案，**不要默默选一个**）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **甲** | 预算**独立于审计**，单独一个账本存储（如 `data/budgets.json` 或 SQLite） | 引入第二种持久化；但**审计的 S1 保持不变** |
| **乙** | 把 `spent` 放进审计，并**修订 S1** 为"只读**决策证据**，但账本字段例外" | 削弱一条不变量；须证明不引入隐藏状态 |
| **丙** | 预算作为**请求显式输入**（调用方传入 `budget_remaining`），系统本身无状态 | 最保守，但把状态管理推给调用方 —— 可能不符合 `FR-007` 的"自动转 exhausted" |

> **我的倾向：甲。** 理由：审计与账本是**两个不同的语义**（证据 vs 账目）。
> 把账目塞进证据链会让"审计恰好 1 条"这条不变量变得含混，
> 也会让 `INV-ADS-012` 的验证复杂化。**但这是架构决策，须你与团队定。**

### 4.2 V2 的架构元素与冻结语义

**课程要求**（`evolution_rounds` 明写）：

> V2 启动时 V1 层冻结（**IMMUTABLE**）；新条目只追加到 `docs2/`。

| 约束 | 具体含义 |
|---|---|
| `docs/architecture/` 变**只读** | V2 的 ASR / 不变量 / ADR / 追踪矩阵全部**新建于 `docs2/architecture/`** |
| V1 的 7 个元素**不得被改** | 竞价引擎是**并列新增** `src/bidding/`，**不是**改 `src/compliance/` |
| **fitness function 已预留** `"bidding"` | `scripts/fitness_functions.py` 的 `ELEMENT_BY_PACKAGE` 已含 `"bidding": "⑧ [V2 预留] 竞价引擎"`，防 S1 误报 |

**顺序不可颠倒。** `compliance` 必须仍在**最后**（它是最终否决权）。
建议新 ADR 明确三者的权力与顺序 —— 这是 V2 最重要的架构决策之一。

## 5. 九个坑（供参考，避免重复付出这些代价）

| # | 坑 | 教训 |
|---|---|---|
| 1 | **monkeypatch 必须打在"使用方的绑定"上** | `selector/__init__` 重导出的名称有**包级绑定**；管道持有**导入引用**。改定义模块对二者均无效，导致变异**假通过**。变异表现在为每条显式列出全部绑定，见 `scripts/mutation_check.py` 的 `why_bound_here` |
| 2 | **同一 `.py` 可被导入成两个模块对象** | `eval/eval_runner.py` 既是 `eval.eval_runner` 又是 `eval_runner`（因测试把 `eval/` 加进了 `sys.path`），**`ReplayReport` 不是同一个类**。打补丁要打两处 |
| 3 | **`bool` 是 `int` 的子类** | `isinstance(True, int)` 为真。LLM 返回 `"confidence": true` 会被当成 `1.0`。须显式排除 |
| 4 | **"恒真断言"没有鉴别力** | 断言"解释不含违禁词"**恒真**（实现无论是否检出都返回安全文本）。必须断言**降级标志与原因码** |
| 5 | **受限环境禁止 `pytest tmp_path`** | 子进程无法建临时目录（`BUG-001`）。用 I/O 边界打桩替代；或**把校验逻辑与读文件分离**以便直接测 |
| 6 | **等长并列的确定性** | `max(hits, key=len)` 的并列由词表顺序决定（`BUG-006`）。用两级判定：先最长、同长取码点最小 |
| 7 | **校验要在入口 fail-fast** | 空候选集若不在预筛阶段拒绝，会让"空 `ad_id`"这类用例**不可达**（P7 设计用例时真实踩到） |
| 8 | **文档会静默过时** | 已发生 4 次漂移（README 说"4 个空目录"、`AGENTS.md` 写"剩余模块"等）。**全部靠人工发现，没有一次靠机制发现** → `TD-027` |
| 9 | **"声明已覆盖"≠"真的覆盖"** | 变异验证第一次运行就抓到 **4 条不具备证伪能力的反例**（其中 2 条是补丁打错绑定导致的假通过）。**若没有它，这 4 条会一直伪装成已覆盖** |
